# v0.1.0 — Deterministic Coding Agent engineering baseline / 确定性 Coding Agent 工程基线

发布日期 / Release date: 2026-09-06

## 中文

`v0.1.0` 固定了项目首个有可复核证据支撑的工程基线。它是一个具备明确失败与恢复语义的
确定性、单 Agent 编码运行时，并不宣称是生产就绪的强多租户 Agent 平台。

### 主要能力

- FSM 显式驱动模型—工具循环，并限制 step、模型调用和工具调用预算。
- 每个 session 使用隔离 workspace，源仓库永远不是写入目标。
- 所有工具统一经过 ToolHarness：读取、有界字面量搜索、精确编辑、可信测试 profile 和结构化命令。
- SQLite schema v3 是持久化与恢复的唯一权威；JSONL 只是可重建导出。
- 支持 crash-window 恢复、轨迹回放、语义 golden tests、有界 context、压缩和离线 Eval。
- OpenAI-compatible 与 Anthropic adapter 对 Provider 故障分类并对 secret 脱敏。
- Linux namespace sandbox 默认禁网，并具备 fail-closed 能力探测、资源限制和进程清理。

### 发布验证

- 默认测试 93/93、语义 golden trajectories 4/4 通过。
- statement coverage 75.6%，高于 70% 门槛；Ruff、mypy、compileall 全部通过。
- wheel 与源码包构建成功，并在全新 Python 3.11 环境完成安装和 CLI 验证。
- 固定离线 Eval：10/10 正常任务端到端成功，4/4 负控制命中，基础设施失败为 0。
- 三仓库 search live follow-up 为 14/15；非 search DeepSeek holdout 为 12/12。
- Python 3.10/3.11 托管 CI 全部通过。

真实 Provider 结果只作为小型 fixture 上的描述性证据，不代表通用编码任务或生产成功率。
本版本支持确定性 ScriptedBackend、显式启用的真实模型 adapter、SQLite 单 Agent session 和能力
探测成功时的原生 Linux namespace sandbox。它明确不支持生产级多租户隔离、通用 Shell、默认
网络、模型驱动依赖安装、Git inspection、多 Agent、UI、RAG 或长期用户记忆。

安装、测试、离线 Eval、Demo 与 replay 的固定复现命令见下方英文部分；命令本身语言无关。

## English

`v0.1.0` freezes the first evidence-backed engineering baseline. It is a deterministic,
single-agent coding runtime with explicit failure and recovery semantics; it is not presented as
a production-ready multi-tenant agent platform.

## Highlights

- Explicit FSM-driven model/tool loop with step, model-call, and tool-call budgets.
- Per-session isolated workspace; the source repository is never the write target.
- Unified ToolHarness for `read_file`, bounded literal `search_files`, exact `edit_file`, trusted
  `restricted_test`, and trusted-profile `run_command` with structured argv.
- SQLite schema v3 as the persistence and recovery authority; JSONL remains a rebuildable export.
- Crash-window recovery, replayable structured trajectories, semantic golden tests, bounded
  context construction, validated compression, and offline Eval.
- OpenAI-compatible and Anthropic adapters with classified Provider failures and secret redaction.
- Linux namespace sandbox with fail-closed capability detection, default-deny network, resource
  limits, and process cleanup.

## Reproduce this exact version

### Install

```bash
git clone https://github.com/1hm-1/coding-agent.git
cd coding-agent
git checkout v0.1.0
uv venv --python 3.11 .venv
uv sync --locked --extra dev
```

Python 3.10 and 3.11 are the hosted-CI release targets. Runtime dependencies are resolved from
`uv.lock`.

### Test and static gates

```bash
PYTHONWARNINGS=error PYTHONPATH=src .venv/bin/python -X dev -m unittest discover -v
.venv/bin/ruff check src tests examples/todo_cli examples/mini_repos
.venv/bin/mypy
PYTHONPATH=src .venv/bin/python -m compileall -q src tests examples/todo_cli examples/mini_repos
```

Native sandbox cases run only when the Linux namespace capability probe succeeds. Unsupported
hosts fail closed or explicitly skip native-only test cases; a skip is not native isolation proof.

### Offline Eval

```bash
release_eval_root="$(mktemp -d /tmp/coding-agent-v0.1.0-eval.XXXXXX)"
PYTHONPATH=src .venv/bin/python -m coding_agent.cli \
  --agent-home "$release_eval_root/agent-home" \
  evaluate --suite examples/eval_suite.json \
  --variant budgeted --repetitions 1 \
  --output "$release_eval_root/report"
```

Expected release result on a native-capable Linux host: 14/14 valid runs, 10/10 normal tasks
end-to-end, 4/4 negative controls observed, zero infrastructure failures, and source invariant
rate 1.0.

### Deterministic demos and replay

```bash
calculator_home="$(mktemp -d /tmp/coding-agent-v0.1.0-calculator.XXXXXX)"
PYTHONPATH=src .venv/bin/python -m coding_agent.cli \
  --agent-home "$calculator_home" run-scripted \
  --source examples/fixture \
  --task "Fix add and run tests" \
  --script examples/scripted_run.json

todo_home="$(mktemp -d /tmp/coding-agent-v0.1.0-todo.XXXXXX)"
PYTHONPATH=src .venv/bin/python -m coding_agent.cli \
  --agent-home "$todo_home" run-scripted \
  --source examples/todo_cli \
  --task "Fix the empty input crash and run tests." \
  --script examples/todo_cli_scripted_run.json
```

Copy the todo command's `session_id`, then run:

```bash
PYTHONPATH=src .venv/bin/python -m coding_agent.cli \
  --agent-home "$todo_home" replay --session-id <session-id>

git diff --exit-code -- examples/fixture examples/todo_cli
```

Expected evidence: calculator uses `read → edit → test` and produces 48 events; todo preserves
`test false → true`, produces 72 events, and replays to `completed`; the final Git diff is empty
because only isolated workspaces were modified.

## Supported scope

- CPython 3.10 and 3.11; Linux/POSIX process semantics.
- Deterministic ScriptedBackend and opt-in OpenAI-compatible/Anthropic model adapters.
- SQLite-backed single-agent sessions, replay, interruption/resume, and defined crash recovery.
- Bounded context/compression and small checked-in offline/live evaluation fixtures.
- Native Linux namespace sandbox only when its capability probe succeeds.

## Explicitly unsupported

- Production-grade strong multi-tenant isolation, OCI image lifecycle, SBOM, or vulnerability
  scanning.
- General shell strings, arbitrary executables, default network, or model-directed dependency
  installation.
- Git inspection tools, multi-agent orchestration, UI, RAG, Skills, or long-term user memory.
- Windows/macOS-equivalent sandbox guarantees.
- A claim of general coding-task or production success rate.

Further capability work remains gated on repeatable Eval failure coverage rather than roadmap
checkboxes.
